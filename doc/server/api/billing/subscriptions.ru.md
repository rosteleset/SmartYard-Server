# `/api/billing/subscriptions` — синхронизация абонентов биллинга

Реализация: `server/api/billing/subscriptions.php`. Внешний маршрут:
`POST /frontend/billing/subscriptions`.

## Авторизация и права

- Требуется `Authorization: Bearer <token>`.
- Доступ проверяется через `authorization->allow()` в `server/frontend.php`.

## Зависимости

- **Точка входа**: `server/frontend.php` → `server/api/billing/subscriptions.php` → класс `\api\billing\subscriptions`.
- **Бэкенды**: `billing->syncAutoBlockByContracts()`, `households` и `customFields`, если переданы значения полей.
- Метод использует `defaultAction = skipMissing`: квартиры вне переданного списка не изменяются.

## Тело запроса

`subscribers` — массив объектов. Каждый объект определяет существующую квартиру по
`subscriberID` (номеру договора) либо по паре `buildingUUID` и `flatNumber`.
Адресная пара имеет приоритет; поиск только по договору должен найти одну квартиру.

Штатные свойства сохраняют отдельную обработку:

- `isActive`: `true`/`1` устанавливает `autoBlock = 0`; `false`/`0` — `autoBlock = 1`.
- `subscriberID`, `buildingUUID`, `flatNumber`: определяют квартиру; прежняя синхронизация договора сохраняется.
- `agreement`, `addressText`: прежние кастомные поля биллинга с автоматическим созданием определений.
- `login`, `password`: обновляют учётные данные квартиры.
- `phones`: импортирует связи телефонных абонентов с квартирой.

### Дополнительные кастомные поля

Остальные свойства сопоставляются по точному имени с `custom_fields.field` для
`apply_to = flat`. Совпавшие значения сохраняются через `modifyValues(..., "patch")`.
Определение поля должно уже существовать. Для добавления нового свойства достаточно
настроить поле, без очередного изменения PHP. Каталог поля не ограничивает сопоставление.

Например, если `branch` настроен как список с вариантами `1` и `2`:

```json
{
  "subscribers": [
    {"subscriberID": 1234, "isActive": true, "branch": 2}
  ]
}
```

- Неуказанные поля сохраняют прежние значения.
- Неизвестные свойства и поля других сущностей игнорируются.
- `null` или пустая строка очищает необязательное дополнительное поле.
- Числа преобразуются в строки, логические значения — в `"1"`/`"0"`. Ноль сохраняется.
- Списки без разрешения произвольного ввода принимают только настроенные варианты.
  Множественный выбор принимает массив или строку с JSON-массивом и хранится как JSON-массив.
- Объекты/массивы принимаются для `editor = json`; прочие одиночные поля требуют скалярных значений.
- Проверяются обязательность, формат числа/JSON и настроенное регулярное выражение.
  Поля-кнопки не принимают сохраняемых значений.
- Имена штатных параметров выше зарезервированы, даже если существует одноимённое кастомное поле.

`isActive` можно не передавать, если указан непустой список `phones` или хотя бы одно
настроенное дополнительное поле. В этом случае `autoBlock` не меняется:

```json
{"subscribers": [{"subscriberID": 1234, "branch": 1}]}
```

Если переданная адресная пара не находит квартиру, объект с дополнительными полями
получает ошибку `customFieldsRequireExactFlatMatch` до изменения квартиры. Переход
к поиску по договору не приводит к успешному ответу с молчаливым пропуском полей.

## Ответы

- **HTTP 200**: `{"subscriptions": <syncResult>}`. Проверяйте `updated`, `invalid`, `notFound`,
  `failed` и `errors`: успешный HTTP-ответ не означает применение всех элементов списка.
- Неверное значение кастомного поля отклоняет объект до изменения квартиры. Остальные
  корректные объекты списка могут обрабатываться. Пример ошибки:

```json
{"index": 0, "error": "invalidCustomFieldValue", "field": "branch", "reason": "invalidOption"}
```

- При недоступности бэкенда кастомных полей объект получает `cantLoadCustomFieldConfiguration`.
- **HTTP 400**: `{"error":"unknown"}`, если бэкенд вернул `false` (`ANSWER(false)`).
- Если бэкенд биллинга недоступен, обработчик возвращает строку `"error"`.

## Регрессионный тест

Требуются PHP 8.1+, `pdo_pgsql`, `mbstring`, серверная зависимость HTMLPurifier
и тестовое подключение к PostgreSQL с правом создания временных таблиц:

```sh
RBT_TEST_PG_DSN='pgsql:host=127.0.0.1;dbname=rbt_test' \
RBT_TEST_PG_USER=rbt_test php tests/billing_subscriptions_custom_fields.php
```

Тест использует настоящий обработчик API, нормализацию биллинга и хранилище кастомных
полей с временными таблицами PostgreSQL внутри отменяемой транзакции. Операции
с квартирами заменены заглушкой, таблицы приложения не изменяются. При необходимости
задайте пароль через переменную окружения `RBT_TEST_PG_PASSWORD`. Если зависимости
находятся вне `server/vendor`, переменная
`RBT_HTMLPURIFIER_AUTOLOAD` может указывать на существующий `HTMLPurifier.auto.php`.
