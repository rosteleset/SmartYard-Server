# Виртуальный домофон

Публичная страница `/v/<код>` связывает посетителя с приложением абонента через WebRTC и существующий Asterisk. Посетитель набирает номер квартиры/офиса или выбирает адресата из списка. Абонент принимает вызов в приложении и может открыть дверь связанного физического домофона. Изменения мобильного приложения не требуются.

## Настройка входа

В RBT откройте список входов дома → меню входа → **Виртуальный домофон**. Включите панель, задайте название/описание, видимость списка и политику вызовов. Сохраните и скопируйте ссылку или скачайте QR-код.

- **Разрешить звонки всем абонентам входа — да:** доступны все связанные квартиры и офисы. При самом вызове действуют штатные блокировки и разрешения VoIP.
- **Нет:** доступны только квартиры с custom field `virtualIntercomCallsEnabled=1`. Пустое поле означает запрет; набор номера не обходит эту проверку.
- Custom field `virtualIntercomName` задаёт публичную подпись, например «Офис Рога и Копыта». Пустое значение показывает «Квартира 12». Поиск учитывает номер и название, адресат вызова не меняется.

Панель привязана к входу, а дверь/реле определяются его настройками. Нужен включённый физический домофон. Настройки и постоянный 12-символьный код ссылки хранятся в существующих custom fields; схема БД не меняется. При повторном сохранении код остаётся прежним. Старый формат ссылок с query-параметром не поддерживается.

Оформление соответствует Теледому: локальные шрифты Source Sans Pro (SIL OFL, лицензия рядом с файлами), синий акцент, белые карточки. Камера появляется при начале вызова, выбор адресата скрывается. Браузер формирует центральный кадр 16:9 без растягивания: canvas 640×360 до 15 кадров/с для превью и SIP, JPEG 480×270 для уведомления. Только локальное превью зеркальное. При подтверждении команды открытия посетитель видит крупное сообщение «Дверь открыта».

## Установка

Требуются настроенный SmartYard, PostgreSQL/Redis, PHP 8.1+ с mbstring, Asterisk с PJSIP, pbx_lua, WebSocket, SRTP, H.264 passthrough и SIP INFO. Рекомендуется `func_md5`; без него используется встроенная Lua-библиотека MD5. Браузеру нужны HTTPS, доступ к камере/микрофону и `HTMLCanvasElement.captureStream`.

Виртуальный домофон использует общий механизм мобильных вызовов из [PR #115](https://github.com/rosteleset/SmartYard-Server/pull/115): независимую отправку начальных push и завершение цикла после обработки одной попытки Dial. Сначала должен быть установлен этот общий код. Штатная обработка `CHANUNAVAIL`, включая паузу 35 секунд, сохраняется и используется также виртуальными вызовами.

Виртуальный домофон использует штатный редактор квартиры для подписи и разрешения вызовов. Для сохранения этих полей требуется регистрация права PUT из [PR #117](https://github.com/rosteleset/SmartYard-Server/pull/117), а для отображения длинных подсказок — исправление переполнения формы из [PR #119](https://github.com/rosteleset/SmartYard-Server/pull/119). Эти общие исправления не дублируются в коде фичи.

1. Установите или обновите RBT штатным способом. `initDB()` выполняет миграцию `v98_virtual_intercom.php`: она регистрирует четыре custom field в существующем каталоге. Штатный `reindex()` регистрирует API и наследование прав дома. Отдельная команда установки фичи не нужна; схема БД и настройки физических устройств не меняются.
2. Параметры связи берутся из существующих конфигов. В `client/config/config.json` используются `asterisk.ws`, `asterisk.sipDomain` и `asterisk.ice`, как во встроенном WebRTC-клиенте RBT. Публичный origin страницы/QR определяется по схеме, домену и порту серверного `api.frontend`. Требуются HTTPS и WSS; при отсутствии настроек форму нельзя включить. Отдельного конфигурационного файла или общего флага включения фичи нет.
3. Подключите `virtual-intercom/features.conf` в действующий Asterisk `features.conf`, сохранив остальные applicationmap. В репозитории include уже добавлен. При необходимости подключите `virtual-intercom/pjsip.conf` для WS-транспорта. Контексты звонка подключаются из `asterisk/virtual-intercom/extensions.lua`.
4. Проксируйте публичный WSS к существующему Asterisk HTTP `/ws` на loopback; штатный nginx-конфиг RBT уже содержит маршрут `/wss`. Эндпоинт `server/asterisk.php` должен оставаться доступным только доверенному Asterisk.
5. Подключите `install/nginx/virtual-intercom.conf` в HTTPS server block. Проверьте пути `/opt/rbt` и сокет PHP-FPM. Он обслуживает короткие ссылки `/v/<код>`, ресурсы и публичный API.
6. Проверьте `nginx -t`, перезагрузите nginx и изменённые модули Asterisk (`res_pjsip`, `features`, `pbx_lua`) в период без активных вызовов. Обновите административную страницу и включите панель у нужного входа.

Браузер получает существующий список `asterisk.ice` без изменений, как административная веб-звонилка. Отдельный TURN-сервис и выдача TURN-реквизитов посетителю не добавляются. Со штатным STUN звук и видео передаются напрямую между браузером и Asterisk; для этого должны быть доступны его RTP-порты. Если сеть посетителя блокирует прямое соединение, вызов без TURN может не установиться.

## Вызов и открытие

Клавиатура автоматически распознаёт ровно пять введённых цифр как код открытия из RBT: кнопка меняется на **Открыть дверь**, ввод маскируется. При удалении цифры или вводе шестой возвращается набор номера. Открытие выполняется только после нажатия кнопки или Enter; камера, микрофон и SIP-вызов не запускаются. Код очищается при переходе к списку и отправке, в URL не передаётся. Выбор адресата из списка всегда означает вызов.

Код проверяется только среди квартир/офисов этого входа, с учётом `manualBlock`, `adminBlock`, `autoBlock`. Сброс кода и отключение панели действуют сразу. Политика разрешения звонков и наличие мобильных устройств не ограничивают действующий код двери. Используется назначенный входу выход физического домофона; открытие записывается штатным событием «код». Схема БД, сами коды и настройки физических устройств не изменяются.

Проверки кода принимаются только через POST с допустимым Origin. Неудачные попытки ограничены пятью за пятиминутный интервал на IP и двадцатью за часовой интервал на вход, независимо от IP. Счётчики резервируются до проверки; правильный код возвращает резерв. Повторная команда одному выходу блокируется на 10 секунд, в том числе после неопределённого результата устройства. Ошибка или таймаут не показываются как успешное открытие.

Сервер проверяет связь квартиры со входом, блокировки, разрешение вызова и актуальное членство абонентов. Посетитель получает только свои временные SIP-реквизиты; номера телефонов, push-токены и реквизиты абонентов ему не выдаются. Частота создания вызовов ограничена по IP и квартире.

Входящий SIP-вызов определяется по аутентифицированному endpoint `vi_<session>`. Asterisk заранее согласует медиа через 183/SDP и создаёт отдельные Local-каналы в контексте `virtual-intercom-dial`. Они вызывают штатный `handleMobileIntercom()`: начальные push используют общую очередь `mobile_push_`, ожидание регистрации, повторы FCM и обработка результата Dial выполняются общим циклом. Модуль фичи задаёт проверку связи push с сессией, параметры привязки/ответа и сохраняет идентификатор виртуального вызова при повторной отправке. Повторные FCM push разрешены сервером только пока вызов находится в состоянии `ringing`; уже переданное провайдеру уведомление отозвать невозможно. Обычные вызовы используют прежние параметры общего обработчика.

Подготовка каждого устройства также общая: `prepareMobileCall()` выделяет SIP-номер, выбирает токен, формирует данные уведомления и вычисляет ключ; `queueMobileCall()` сохраняет начальный push и данные повторов FCM. Номер берётся непосредственно из результата Redis INCR, без отдельного GET, который мог прочитать уже следующий номер другого вызова. Проверки доступа и выдача SIP-прав остаются у соответствующего маршрута: виртуальным устройствам не создаются обычные `mobile_extension_`/`mobile_token_` реквизиты. В PHP уведомления собирает и отправляет единый обработчик; модуль виртуального домофона проверяет сессию и задаёт её кадр, inband-видео и DTMF через SIP INFO.

Pre-dial `b()` связывает реальный PJSIP-канал с сессией и включает `DYNAMIC_FEATURES` только на нём. `U()` фиксирует ответившее устройство. DTMF `5` вызывает Gosub: сервер повторно проверяет вход, выход, членство, блокировки, победивший канал/uniqueid и срок действия перед `openLock(output)`.

Команда резервируется до обращения к устройству. Медленное открытие не блокирует отмену вызова и не перезаписывает завершённое состояние. Повторное нажатие не повторяет неопределённую команду после таймаута. Статус `sent` означает успешный возврат драйвера, а не показание датчика двери.

Максимальная длительность PBX-вызова — 150 секунд. Временные реквизиты абонента сохраняются ещё в пределах часа с момента подготовки для позднего REGISTER/unregister; его контекст запрещает исходящие вызовы, REFER и SUBSCRIBE. Это не продлевает право ответа или открытия. Камера и микрофон отключаются сразу при завершении, независимо от ответа HTTP API. Кадры удаляются при завершении; незавершённые данные ограничены TTL/штатной очисткой memfs.

## Проверки

```sh
php tests/virtual-intercom/service_test.php
php tests/virtual-intercom/panels_test.php
php tests/virtual-intercom/codes_test.php
lua tests/virtual-intercom/push_test.lua
lua tests/virtual-intercom/preparation_test.lua
php tests/virtual-intercom/push_adapter_test.php
lua tests/asterisk/mobile_intercom_test.lua
luac -p asterisk/extensions.lua
luac -p asterisk/virtual-intercom/extensions.lua
```

`preparation_test.lua` и `push_adapter_test.php` также принимают путь к предыдущей версии исходников для сравнения SIP-реквизитов и данных уведомлений. Они используют подменённые Redis, SIP и push-провайдер и не отправляют внешние запросы.

С установленными Playwright и Chrome выполните `node` для `preview_test.cjs`, `media_order.cjs`, `door_feedback.cjs`, `flat_names.cjs`, `codes_ui.cjs`, `admin_form.cjs` в том же каталоге. Путь к Chrome можно задать через `CHROME_PATH`. Административному тесту нужны установленные `client/lib` либо `VI_ADMIN_LIBS` с jquery, jquery-ui, bootstrap.bundle, adminlte CSS и qrcode. Проверки используют подменённый драйвер двери, синтетические камеры и подменённые HTTP/SIP, не вызывают абонентов и не отправляют команд двери. H.264 проверяется между настоящими локальными WebRTC-пирами.

`probe.py --prepare <каталог>` и `--run <результат.json>` проверяют DYNAMIC_FEATURES через loopback SIP в отдельном Asterisk. `registration_probe.py --run --root <установка>` проверяет регистрацию/отказ исходящего вызова временного абонента без сессии и push. `browser_smoke.cjs <URL>` проверяет опубликованную страницу; его флаг `--call` действительно звонит выбранному абоненту, поэтому применяется только для согласованной проверки.

На устройстве отдельно проверьте ответ, звук, движение кадра, повторный вызов и кнопку открытия. Chromium с iPhone User-Agent не заменяет Safari на телефоне.

## Отключение

Выключите панель в настройках входа. Это запрещает новые вызовы и команды открытия, включая уже созданные сессии. Установленный разговор завершается штатно или по таймеру. Для удаления фичи снимите её include и маршруты nginx, восстановите совместимые PHP/Lua-файлы. Не сбрасывайте всю установку и не очищайте Redis целиком.
