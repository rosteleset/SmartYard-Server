В релиз вошли виртуальный домофон для звонков из браузера по ссылке или QR-коду и массовая отправка текстовых сообщений
в мобильное приложение с выбором адресов получателей. Добавлены бета-поддержка контроллера Rubetek RACS-1101 и
камер Dahua, дата начала действия автомобильных номеров и настройка SIP over TLS для мобильных вызовов.
Отправка push о вызове теперь выполняется независимо для каждого устройства, а автоконфигурация оборудования
больше не задерживает выполнение остальных задач минутного cron.

## ✨ Новые возможности

- Добавлен виртуальный домофон: посетитель может позвонить абоненту из браузера по ссылке или QR-коду.
  Поддерживаются видеосвязь, открытие двери абонентом и открытие персональным кодом квартиры. Панель привязывается
  к существующему входу. В WEB-интерфейсе можно настроить название, отображение списка квартир и разрешение звонков.
- Добавлена бета-поддержка контроллера доступа Rubetek RACS-1101, обработка логов устройства будет добавлена в
  следующих релизах.
- Добавлена бета-поддержка камер Dahua, включая отдельный сервис получения событий движения для FRS/LPRS.
- Расширена массовая отправка текстовых сообщений в мобильное приложение: получателей можно выбрать по дому,
  улице, населённому пункту, району, региону или всем адресам. Сообщения сохраняются во входящих приложения и
  сопровождаются push. Перед отправкой показывается число получателей. Доставка выполняется через очередь и
  продолжается после закрытия страницы. Для интеграций добавлены `GET/POST /api/inbox/broadcast`.
- Мобильный `getSettingsList` теперь возвращает каталог доступных услуг, подключённые услуги квартиры
  и статус владельца договора. Каталог и услуги по умолчанию можно настроить для инсталляции и отдельных домов.
- Добавлен выбор SIP over TLS для мобильных вызовов.
- Для автомобильных номеров добавлены дата и время начала действия в WEB-интерфейсе и мобильном API.
- В мобильный API добавлена проверка формата белорусских и армянских автомобильных номеров.
- В мобильных настройках теперь возвращаются поддерживаемые форматы автомобильных номеров
  (`supportedPlateNumberFormats`) и настроенная версия LPRS API (`lprsVersion`). Также добавлен отдельный метод
  `POST /mobile/lprs/listSupportedPlateNumberFormats`.
- В ответ `listNumbersV2` добавлен идентификатор наблюдения `watcherId`.

## 🛠️ Улучшения

- В WEB-журнале событий снимки от FALPRS и медиасервера выделены разными цветами: источник указан во всплывающей
  подсказке.
- В статистику квартир добавлено количество квартир с SIP-домофонией. Счётчик "Другие" мобильные устройства удалён.
- Увеличена ширина полос прокрутки в WEB-интерфейсе.

## ⚡ Производительность

- Автоконфигурация устройств больше не блокирует минутный cron. В конфигурации сервера можно изменить количество
  одновременно выполняемых задач и максимальное время выполнения каждой задачи.
- Ускорена отправка первоначальных push-уведомлений о входящем вызове: запросы для разных мобильных устройств теперь
  выполняются параллельно. Медленный ответ push-сервиса для одного устройства больше не задерживает отправку остальным.
- Оптимизированы запросы журнала событий по дому и входу для разных форматов JSON в ClickHouse. Таймаут запросов
  ClickHouse увеличен с 5 до 30 секунд.

## ⚠️ Обновление

### Asterisk

Чтобы применить параллельную отправку первоначальных push и исправление повторных вызовов, после обновления
перезагрузите Lua dialplan:

```bash
asterisk -rx "module reload pbx_lua"
```

### Push-сервис

Для исправления обработки транспортных ошибок перезапустите активные экземпляры push-сервиса:

```bash
systemctl try-restart 'push@*.service'
```

Если используется прежний юнит `rbt-push.service`, выполните вместо этого:

```bash
systemctl try-restart rbt-push.service
```

### MongoDB-индексы файлов

После обновления исправьте ранее созданные индексы:

```bash
php /opt/rbt/server/scripts/fixes/repairMongoFileIndexes.php
```

Скрипт создаёт и проверяет корректные индексы, затем удаляет ошибочные. Файлы и остальные индексы не затрагиваются;
повторный запуск безопасен. Создание индексов может временно повысить нагрузку на базу.

### Короткие RFID-коды Akuvox

Ранее загруженные короткие RFID могут не перезаписаться при обычной автоконфигурации, поскольку после нормализации
они совпадают с RFID в базе SmartYard. Если такие ключи не работают, удалите соответствующие старые записи
в WEB-интерфейсе домофона, затем запустите автоконфигурацию. Из базы SmartYard ключи удалять не нужно.

### Каталог мобильных услуг

Параметр `mobile.default_services` в `/opt/rbt/server/config/config.json` задаёт каталог услуг инсталляции.
Без него дома, у которых не задано дополнительное поле `services`, получают весь встроенный каталог.
Чтобы показывать только предоставляемые вами услуги, задайте каталог по
[примеру конфигурации](../../server/config/config.sample.json5).

`byDefault` определяет, включается ли услуга для квартир автоматически, а `canChange` разрешает изменение тарифа.
Оба флага задаются строками `"t"` или `"f"`. Дополнительное поле дома `services` выбирает услуги из этого каталога,
а одноимённое поле квартиры задаёт её подключённые услуги.

### Очередь автоконфигурации

Дополнительные параметры `backends.queue` позволяют изменить ограничения:

```json
{
    "backends": {
        "queue": {
            "backend": "internal",
            "max_concurrent_tasks": 25,
            "task_timeout": 3600
        }
    }
}
```

`max_concurrent_tasks` ограничивает общее число одновременных задач автоконфигурации камер и домофонов.
`task_timeout` задаёт максимальное время одной задачи в секундах. Без этих настроек используются указанные значения.

### Виртуальный домофон

Для использования новой функции нужны HTTPS и рабочие настройки браузерной SIP-связи в
`/opt/rbt/client/config/config.json`: `asterisk.ws`, `asterisk.sipDomain` и при необходимости `asterisk.ice`.
Подключите Nginx-конфигурацию и перезагрузите обработчик открытия двери в Asterisk:

```bash
mkdir -p /etc/nginx/rbt.d
ln -s /opt/rbt/install/nginx/virtual-intercom.conf /etc/nginx/rbt.d/virtual-intercom.conf
nginx -t && systemctl reload nginx
asterisk -rx "module reload features"
```

После этого настройте виртуальный домофон в списке входов дома. Вход должен быть связан с включённым физическим
домофоном и его выходом реле. Чтобы разрешить звонки только в выбранные квартиры, отключите в настройках виртуального
домофона "Разрешить звонки всем абонентам входа" и включите поле "Разрешить звонки с виртуального домофона"
в настройках нужных квартир.

### SIP over TLS

TLS включается отдельно у нужного сервера `backends.sip.servers[]` через `sip_mobile_transport: "tls"`
и `sip_tls_port`. Существующий TCP остаётся значением по умолчанию.
До включения настройте TLS-транспорт SIP-сервера и доверенный сертификат; мобильный клиент также должен
поддерживать TLS. Для iOS при использовании TURN проверьте поддержку TURN over TLS.
См. [инструкцию](../../doc/server/backends/sip/README.ru.md).

### События движения Dahua

Для получения событий движения назначьте камере Dahua сервер FRS/LPRS, добавьте секцию `hw.dahua` из
`/opt/rbt/server/services/event/config.sample.json` в конфигурацию event-сервиса и запустите `event_dahua.service`
по [инструкции установки сервисов событий](../../install/11.event.md).

### Пользовательские бэкенды FRS

Бэкенды, напрямую наследующие абстрактный `frs`, должны реализовать:

```php
getAdditionalFeaturesFrs(): array
getSupportedPlateNumberFormats(): array
```

Бэкенды, наследующие эти методы от `frs/internal`, не требуют изменений.

### Пользовательские бэкенды households

Бэкенды, напрямую наследующие абстрактный `households`, должны реализовать новые методы:

```php
getHouseServices($houseId): ?array
getFlatServices($flatId): ?array
getAddressBroadcastRecipientCount($by, $query)
queueAddressBroadcast($by, $query, $title, $msg, $action = "inbox")
updatePlateValidFrom($number, $validFrom = null, $countryCode = 'ru')
updateFlatPlateValidFrom($flatId, $number, $validFrom = null, $countryCode = 'ru')
```

Сигнатура добавления автомобильного номера теперь включает `validFrom` перед `validTo`:

```php
addFlatPlateNumber($flatId, $number, $validFrom = null, $validTo = null, $countryCode = 'ru')
```

Бэкенды на основе `households/internal` получают новые методы автоматически; изменения требуются только при
переопределении `addFlatPlateNumber()` или его вызове со старым порядком аргументов.
