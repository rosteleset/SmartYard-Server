# 🚀 SmartYard-Server 1.2.0

[English](README.md) | [Русский](README.ru.md)

This release introduces push notifications when a door is opened by a face from a selected group and improves
automatic grouping of saved faces by similarity. License plates can now include a country and expiration date. The web
interface now provides administrative event logs and summary statistics for flats, equipment, RFID keys and mobile
devices. The release also adds OMNY VDP-10M, OMNY VDP-10S and BAS-IP CR-02BD support, and allows multiple service
companies to be assigned to a house.

## ✨ Features

- Added OMNY VDP-10M and OMNY VDP-10S intercom support.
- Added BAS-IP CR-02BD network reader support.
- Added face-group opening tracking: the subscriber receives a push notification when the door is opened by any face
  in the selected group.
- Added country codes, expiration dates and Russian format validation for license plates, together with the
  `listNumbersV2` mobile API method.
- Added event logs for flats, entrances and houses with filtering, previews and CSV export.
- Added a statistics page for flats, equipment, RFID keys and mobile devices.
- Houses can now be assigned to multiple service companies.
- Added Forpost archive range support.
- Added `GET /mobile/address/plogInfo/{eventUuid}` for retrieving an event by UUID, including its flat, entrance name,
  event type and snapshot URL.
- Added support for instance-specific Nginx configuration in `/etc/nginx/rbt.d/*.conf`. These files are not affected
  by repository updates. See the [Nginx guide](../../install/08.nginx.md) for details.

## 🛠️ Improvements

- Automatic grouping now processes all saved subscriber faces, preserves existing groups and adds new similar faces
  to them.
- Camera and intercom IDs are now shown in equipment dropdowns and search results.
- The billing subscriber synchronization API can now update configured flat custom fields supplied by the billing
  system using their field names.
- Email configuration now supports SMTP encryption modes and a connection timeout.

## 🐛 Bug Fixes

- Fixed snapshot URL generation for Flussonic and Sesame DVR when `secure_token` is configured.
- Fixed the video stream URL sent in incoming-call push notifications. The URL is now generated by the DVR backend
  instead of using the raw `dvrStream` value.
- Fixed license plate association with flats when generating LPRS opening events.
- Fixed SIP event parsing for the updated Ufanet log format.
- Fixed Zabbix SIP registration status mapping for Akuvox-compatible intercoms.
- Fixed an endless loading spinner after closing the add-camera form without saving.
- Fixed visibility filtering for cameras that are assigned to both entrances and houses.
- Fixed camera group display mode persistence when using the cyclic group switch button.
- Fixed handling of empty and nested camera groups.
- Restored entrance IDs in the mobile address API response for exact camera mapping.
- Added missing translations for CCTV-specific flat custom fields.
- Fixed flat custom field updates for users with house editing permission.

## 🔌 Compatibility

- License plate data was moved from `houses_flats.cars` to dedicated tables. Existing data is migrated automatically
  by PostgreSQL migration v97; no separate command is required.
- Custom `frs` and `households` backend contracts have changed. Backends based on the standard implementations require
  no modifications.

## 📚 Documentation

- Added [Postman collections](../../doc/postman) for the SmartYard APIs.

## 📝 Maintenance

- The experimental Makefile was removed and replaced with an experimental `justfile`-based installer.

## ⚠️ Upgrade Notes

### Event tracking

Event tracking must be enabled in `/opt/rbt/server/config/config.json` to receive push notifications when a door is
opened by a face from a selected group:

```json5
{
    "mobile": {
        "events_tracking": true
    }
}
```

### System statistics

A new system statistics page is available in the web interface. It displays summary information about flats,
equipment, RFID keys and mobile devices. On existing installations, the page is not enabled automatically. To enable
it, add the following backend configuration to `/opt/rbt/server/config/config.json`:

```json5
{
    "backends": {
        "statistics": {
            "backend": "internal",
            "inactiveDeviceDays": 30,
            "cacheTtl": 300
        }
    }
}
```

`inactiveDeviceDays` specifies the number of days without activity after which a mobile device is considered inactive.
`cacheTtl` specifies the statistics cache lifetime in seconds.

Then reindex API permissions:

```bash
php /opt/rbt/server/cli.php --reindex
```

### Zabbix templates

If you use Zabbix to monitor Akuvox-compatible intercoms, re-import the monitoring templates after upgrading:

```bash
php /opt/rbt/server/cli.php --init-monitoring-config
```

### Custom FRS backends

Backends that directly extend the abstract `frs` backend must implement or update these methods:

```php
getFaceGroupIdFrs(int $flat_id, int $subscriber_id, int $face_id): ?int
getFacesFromGroupIdFrs(int $group_id): array
clusterFacesBySimilarityFrs(string $prefix_name, int $subscriber_id, int $flat_id): bool
isLikedFlagFrs($flat_id, $subscriber_id, $face_id, $event_uuid, $is_owner): array
```

`isLikedFlagFrs()` must now return both the liked state and the matched face ID:

```php
[$is_liked, $registered_face_id]
```

Backends that extend `frs/internal` inherit these methods and require no changes.

### Custom households backends

Custom `households` backends must implement the following method for face groups:

```php
getSubscriberGroupById($subscriberGroupId): ?string
```

The `households` contract was also extended to support license plate country codes and expiration dates:

```php
getFlatPlateNumbers($flatId)
getFlatPlateNumbersV2($flatId)
getFlatLicensePlates($flatId)
addFlatPlateNumber($flatId, $number, $validTo = null, $countryCode = 'ru')
removeFlatPlateNumber($flatId, $number, $countryCode = 'ru')
modifyFlatPlateNumbers($flatId, $cars)
updatePlateValidTo($number, $validTo = null, $countryCode = 'ru')
updateFlatPlateValidTo($flatId, $number, $validTo = null, $countryCode = 'ru')
```

Backends that extend `households/internal` inherit these methods and require no changes.
