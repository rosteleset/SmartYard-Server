# 🚀 SmartYard-Server 1.1.0

[English](README.md) | [Русский](README.ru.md)

В этот релиз вошли поддержка OMNY VDP-10L, расширенные возможности массового импорта RFID-ключей и управление
видимостью групп камер для отдельных квартир. Также появились новые точки расширения мобильного API, возможность при
добавлении абонента сразу указать, является ли он владельцем квартиры, и явная настройка хранилища снимков событий и
экспортированных видеофрагментов.

## ✨ Новые возможности

- Добавлена поддержка домофона OMNY VDP-10L.
- Массовый импорт RFID-ключей дополнен преобразованием DEC/HEX, изменением порядка байтов и предварительным
  просмотром результата.
- Добавлена массовая привязка RFID-ключей к квартирам из карточки дома.
- Добавлена возможность указывать, каким квартирам видна каждая группа камер.
- При добавлении абонента через веб-интерфейс или API теперь можно сразу указать, является ли он владельцем квартиры.
- Добавлены точки расширения для адаптации поведения и ответов мобильного API без замены штатных обработчиков.

## 🛠️ Улучшения

- Расширена фильтрация диагностических сообщений Akuvox-совместимых домофонов в сервисе событий.
- Добавлен явный выбор `gridfs` или `tmpfs` для хранения снимков событий и экспортированных видеофрагментов.

## ⚡ Производительность

- Сокращено количество лишних записей в базу данных при мобильной авторизации за счёт ограничения частоты обновления
  метаданных устройства.

## 🐛 Исправления

- Исправлена очистка временных файлов при сбоях DVR-экспорта и сохранения снимков событий.
- Автоконфигурация включает возможность отмены исходящего вызова аппаратными кнопками на Akuvox-совместимых домофонах.
- Обработка коротких номеров квартир в Asterisk ограничена устаревшими моделями Sokol, для которых она изначально и
  предназначалась (модели `IS SOKOL (rev.2)` и `IS SOKOL PLUS LEGACY (rev.5)`).

## 🔌 Совместимость

- MongoDB GridFS теперь используется по умолчанию для новых снимков событий и DVR-экспортов.
- Параметр `tmpfs.ttl_max` удалён. Срок хранения файлов определяется значением `metadata.expire`.
- Удалена устаревшая поддержка SQLite. Для основной реляционной базы данных теперь поддерживается только PostgreSQL.
- Изменены сигнатуры некоторых методов абстрактного бэкенда `households`, используемых пользовательскими бэкендами.

## 📚 Документация

- Обновлена [настройка syslog](../../install/11.event.md#akuvox-omny) для Akuvox-совместимых домофонов и OMNY VDP-10L,
  включая перенаправление UDP-порта 514.
- В [инструкцию по MongoDB](../../install/06.mongo.md#fix-for-linux-kernel-619-incompatibility) добавлено описание
  обходного решения для запуска MongoDB 8.0+ на ядре Linux версии
  6.19 ([Описание проблемы](https://jira.mongodb.org/browse/SERVER-121912)).

## ⚠️ Обновление

### Пользовательские бэкенды households

Метод `households::addSubscriber()` получил необязательный седьмой аргумент `$owner`:

```php
addSubscriber($mobile, $name, $patronymic, $last, $flatId, $message, $owner = false)
```

Пользовательские бэкенды `households`, переопределяющие этот метод, должны обновить его сигнатуру. Для бэкендов,
наследующих реализацию от `households/internal`, изменения не требуются.

Контракт дерева путей `households` расширен для управления видимостью камер по квартирам:

```php
addRootPathNode($tree, $text, $icon, $type = "list", $visibleForFlats = null)
addPathNode($parentId, $text, $icon, $type = "list", $visibleForFlats = null)
modifyPathNode($nodeId, $text, $icon, $type = null, $visibleForFlats = false)
getPathVisibleForFlats($nodeId)
```

Бэкенды, напрямую наследующие абстрактный `households`, должны обновить сигнатуры трёх методов и реализовать
`getPathVisibleForFlats()`, иначе они не загрузятся. Бэкенды на основе `households/internal` наследуют новую реализацию
и не требуют изменений.

### Хранилище файлов

Новые снимки событий и DVR-экспорты теперь сохраняются в MongoDB GridFS независимо от наличия бэкенда `tmpfs`.
Чтобы новые файлы, как и раньше, сохранялись в `tmpfs`, добавьте эти параметры в `config.json` **до обновления
SmartYard**. Иначе файлы, созданные после обновления и до изменения конфигурации, будут сохранены в GridFS:

```json5
{
    "backends": {
        "plog": {
            "camshot_storage": "tmpfs"
        },
        "dvrExports": {
            "storage": "tmpfs"
        }
    }
}
```

Существующие файлы автоматически не переносятся. Не удаляйте секцию `backends.tmpfs` из конфигурации, иначе
содержимое старых файлов станет недоступно. Параметр `tmpfs.ttl_max` больше не используется: срок хранения
определяется полем `metadata.expire` каждого файла.

Для снимков событий `metadata.expire` рассчитывается по параметру `backends.plog.ttl_camshot_days` в днях. Для
DVR-экспортов используется параметр `backends.dvrExports.dvr_files_ttl` в секундах. Значение по умолчанию — `259200`
секунд (3 дня). Файлы без `metadata.expire` автоматически не удаляются.
