# RBTAgent controller and overlay gateway

This step enables the optional
[RBTAgent](https://gitap.ru/SesameWare/RBTAgent) controller in SmartYard Server. It
adds signed HTTPS pairing and synchronization, declarative overlay state, and a
root-owned WireGuard/AmneziaWG gateway reconciler.

The controller does not use the HTTPS certificate as the pairing identity. TLS
is still validated normally, while pairing is pinned to a persistent Ed25519
application key. Renewing the site certificate therefore does not break paired
agents.

This module implements RBT Agent protocol v2 and requires RBTAgent 0.2 or newer.
Upgrade the controller and agent as one operation. Before replacing an active
protocol v1 agent, disable or revoke its overlay with the old agent and
controller so obsolete runtime network objects are removed cleanly.

## Requirements

- PostgreSQL and the PHP `pdo_pgsql` and `sodium` extensions;
- `iproute2`, `nftables`, `systemd`, `logrotate`, and `sysctl`;
- `wireguard-tools` (`wg`) or AmneziaWG tools (`awg`);
- a public HTTPS URL routed to this SmartYard installation.

Back up the SmartYard database and configuration before enabling the module.

## Database

Install or upgrade SmartYard normally. Schema version 95 creates the
`edge_agent_*` tables through the standard migration path:

```bash
cd /opt/rbt
sudo -u www-data php server/cli.php --init-db
```

`server/edge-agent-controller/bin/migrate.php` is retained as a standalone
recovery tool. Regular installations should use `server/cli.php --init-db`.

## Persistent directories

```bash
install -d -o www-data -g www-data -m 0750 /var/lib/rbt-agent-controller
install -d -o www-data -g www-data -m 0750 /var/log/rbt-agent-controller
install -d -o root -g root -m 0700 /var/lib/rbt-agent-controller/gateway/keys
install -d -o root -g root -m 0755 /var/lib/rbt-agent-controller/gateway-public
install -d -o root -g root -m 0750 /var/log/rbt-overlay-gateway
```

Initialize the persistent controller identity as the PHP service user:

```bash
sudo -u www-data env \
  RBT_AGENT_RBT_CONFIG=/opt/rbt/server/config/config.json \
  RBT_AGENT_IDENTITY=/var/lib/rbt-agent-controller/controller-identity.json \
  php /opt/rbt/server/edge-agent-controller/bin/init-identity.php
```

Initialize a root-owned gateway key. Use `wg` initially unless AmneziaWG is
installed and tested on the host:

```bash
env \
  RBT_AGENT_GATEWAY_STATE=/var/lib/rbt-agent-controller/gateway \
  RBT_AGENT_GATEWAY_PUBLIC_STATE=/var/lib/rbt-agent-controller/gateway-public \
  php /opt/rbt/server/edge-agent-controller/bin/init-gateway-key.php wg-rbt0 wg
```

The private gateway key must remain readable only by root. The PHP controller
reads the exported public key from `gateway-public`.

## SmartYard configuration

Add the public controller URL to `server/config/config.json`:

```json
{
  "edgeAgentController": {
    "publicUrl": "https://rbt.example.com"
  }
}
```

Add `edgeAgents` to the `modules` array in `client/config/config.json5`. Run the
normal SmartYard reindex command afterwards so API rights and client modules are
registered.

## nginx

Install the supplied snippet and include it only from the HTTPS virtual host:

```bash
install -o root -g root -m 0644 \
  /opt/rbt/install/nginx/rbt-agent-controller.conf \
  /etc/nginx/snippets/rbt-agent-controller.conf
```

The `rbt_force_ssl` template already includes this snippet. It exposes
`/rbt-agent/v2/` through `server/rbt-agent.php`. Apply the include to the active
HTTPS virtual host, then verify and reload nginx:

```bash
nginx -t
systemctl reload nginx
```

Do not put user-session authentication in front of this endpoint. Agent requests
have their own Ed25519 signatures, replay protection, timestamp window, and
monotonic sequence validation.

## Gateway service

```bash
install -o root -g root -m 0644 install/systemd/rbt-overlay-gateway.service /etc/systemd/system/
install -o root -g root -m 0644 install/systemd/rbt-overlay-gateway.timer /etc/systemd/system/
install -o root -g root -m 0644 install/sysctl/90-rbt-agent-overlay.conf /etc/sysctl.d/
install -o root -g root -m 0644 install/logrotate/rbt-agent-controller /etc/logrotate.d/rbt-agent-controller
install -o root -g root -m 0644 install/logrotate/rbt-overlay-gateway /etc/logrotate.d/rbt-overlay-gateway
sysctl --system
systemctl daemon-reload
systemctl enable --now rbt-overlay-gateway.timer
systemctl start rbt-overlay-gateway.service
```

The gateway reconciler reads desired state from PostgreSQL and applies the full
WireGuard peer set, routes, and the 1:1 NAT table atomically. RBT never executes
network commands through PHP.

## Verification

```bash
systemctl status rbt-overlay-gateway.timer
systemctl status rbt-overlay-gateway.service
journalctl -u rbt-overlay-gateway.service -n 100 --no-pager
tail -n 100 /var/log/rbt-agent-controller/events.jsonl
nft list table inet rbt_agent_overlay
wg show wg-rbt0
```

In the SmartYard UI, open **RBTAgent**, create a pairing invitation, pair the
agent, authorize managed mode with the local agent management secret, assign an
overlay pool, and add 1:1 mappings. A mapping is active only when desired and
actual generations match.

## Rollback

Disable the timer before removing an overlay configuration:

```bash
systemctl disable --now rbt-overlay-gateway.timer
systemctl stop rbt-overlay-gateway.service
nft delete table inet rbt_agent_overlay
ip link delete wg-rbt0
```

Restore the database and configuration backup if the schema itself must be
rolled back. Do not delete controller identity or agent pairing state during a
normal application or TLS certificate update.
