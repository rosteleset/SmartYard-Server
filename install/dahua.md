# Dahua: драйвер камеры и приём событий движения

## Статус и область поддержки

Начальная реализация для камер **Dahua IPC с совместимым CGI API**, основанная на
Dahua IPC HTTP API v1.40. Модель **DH-IPC-HFW1420SP-0280B** была исходной целью
разработки, но драйвер не ограничивает подключение по названию модели.
Совместимость определяется доступными CGI-командами и форматом зон движения.
Реализация проверена на CGI-фикстурах и локальном HTTP-эмуляторе; совместимость с
физической камерой и её прошивкой должна быть подтверждена по процедуре ниже.
Это не заявление о поддержке всех Dahua.

Две независимые части:

- PHP-драйвер `server/hw/ip/camera/dahua/dahua.php`: информация об устройстве,
  JPEG-снимки, включение/отключение движения и до четырёх прямоугольных зон.
- Node.js-адаптер `server/services/event/services/DahuaService.js`: постоянные
  HTTP-подписки на `VideoMotion`, восстановление подключения и передача состояния
  в штатный `/internal/actions/motionDetection` (FRS/LPRS).

Видео по-прежнему принимает медиасервер. Адаптер не получает и не анализирует видеопоток,
не включает архивную запись и не добавляет собственные записи в ClickHouse `syslog`/`plog`.

Драйвер принимает только документированную сетку **22 столбца × 18 строк, 4 окна**
`MotionDetect[0].MotionDetectWindow[n].Region[row]`. Другой формат вызывает ошибку
до записи настроек. Проценты из редактора RBT округляются наружу до ячеек сетки;
фактическая зона может быть немного больше нарисованной. После записи драйвер
повторно читает настройки и проверяет совпадение всех окон.

Чувствительность, пороги, расписание и действия по тревоге сохраняются. Настройте их
в веб-интерфейсе камеры; убедитесь, что расписание разрешает детекцию в нужные часы.
Драйвер намеренно **не управляет** сетью, NTP, часовым поясом, OSD и паролями;
автоконфигуратор пропускает эти разделы для Dahua. Сброс и первичная активация не
поддерживаются, явная команда перезагрузки поддерживается.

## 1. Камера в RBT

1. Активируйте камеру штатным способом. Создайте учётную запись с правами чтения CGI,
   получения снимков/событий и настройки детекции.
2. Установите файлы этой версии RBT. Модель `dahua.json` загружается обычным механизмом
   списка моделей; миграция БД не требуется.
3. Выберите **Dahua IPC (CGI, 22×18)**.
4. В поле адреса камеры задайте базовый HTTP(S) URL, например
   `http://rbt@192.0.2.10`. Имя пользователя можно указать в URL, без пароля;
   если его нет, используется `admin`. Пароль укажите в поле «Учётные данные».
5. Настройте поток/адрес DVR, домовые привязки и права просмотра обычным способом.
6. Нарисуйте зоны движения и примените штатную автоконфигурацию камеры. Пустой список
   зон отключает детектор и очищает старые маски всех четырёх окон.

Ручной вызов автоконфигурации **меняет детекцию на камере**. Выполняйте его только
после проверки сохранённых в RBT зон:

```sh
cd /opt/rbt/server
php cli.php --autoconfigure-device=camera --id=CAMERA_ID
```

## 2. Адаптер событий

Требуются Node.js 22+ и обычная установка event-service. Новых npm-зависимостей нет.
На сервере адаптера должен быть исходящий HTTP(S)-доступ к камерам и доступ к
внутреннему API RBT. Входящие UDP-порты/HTTP-webhook настраивать не нужно.

В существующий `server/services/event/config.json` добавьте секцию, сохранив другие
настройки. Адрес `api.internal` — доверенный внутренний адрес RBT; не публикуйте его
в Интернет.

```json
{
  "api": { "internal": "http://127.0.0.1/internal" },
  "hw": {
    "dahua": {
      "cameras": [
        {
          "url": "http://192.0.2.10",
          "ip": "192.0.2.10",
          "username": "rbt",
          "passwordEnv": "RBT_DAHUA_CAM1_PASSWORD"
        }
      ]
    }
  }
}
```

- `url`: базовый адрес камеры, без логина/пароля, пути RTSP, query и fragment.
- `ip`: **IP, записанный для этой камеры в RBT (`cameras.ip`)**, а не адрес сервера
  адаптера. Он используется существующим обработчиком для поиска камеры. После
  добавления/изменения камеры RBT определяет IP из её URL.
- `username`: пользователь CGI, по умолчанию `admin`.
- `passwordEnv`: имя переменной окружения с паролем. Альтернатива — `password` в
  защищённом серверном конфиге. Секреты не должны попадать в Git или клиентские файлы.
- `enabled: false`: не подписываться на эту запись.

Список подписок пока задаётся **отдельно** от карточек камер RBT; автоматического
обнаружения, обновления списка из БД и горячей перезагрузки нет. После изменения
списка/пароля перезапустите адаптер. Один IP может быть указан только один раз.
При отключении/удалении камеры в RBT также отключите/удалите её запись в конфигурации
адаптера: изменения карточки автоматически на подписку не распространяются.
Несколько камер за одним NAT-адресом и многоканальные NVR эта версия не поддерживает:
обрабатывается канал Dahua `index=0`, и в RBT должна быть однозначная привязка IP.

Для передачи событий в распознавание в карточке камеры должен быть выбран FRS/LPRS.
Без этой привязки штатный RBT отвечает `FRS not enabled on this stream` и не запускает
распознавание. Получение событий само по себе не означает разрешение на открытие двери.

Запуск вручную из каталога event-service:

```sh
npm run dahua
```

Сервис запускается явно, а не через wildcard `npm start`: существующие установки без
`hw.dahua` не должны неожиданно получить ещё один процесс.

Для systemd предусмотрен `install/systemd/event/event_dahua.service`. Пример установки
после заполнения конфигурации (адаптируйте пути, если RBT установлен не в `/opt/rbt`):

```sh
sudo install -m 644 /opt/rbt/install/systemd/event/event_dahua.service /etc/systemd/system/event_dahua.service
sudo systemctl daemon-reload
sudo systemctl enable --now event_dahua.service
journalctl -u event_dahua.service -f
```

Переменную пароля для systemd можно задать в `/etc/rbt/dahua-events.env`, читаемом
через `EnvironmentFile`. Пример **формата**, не настоящий пароль:

```text
RBT_DAHUA_CAM1_PASSWORD="REPLACE_WITH_CAMERA_PASSWORD"
```

Ограничьте доступ к файлам конфигурации и секретов (например, root:rbt, `0640`).
Используется HTTP Digest (MD5/SHA-256 и sess-варианты); автоматического перехода к
Basic нет. HTTPS проверяет сертификат: добавьте доверенный CA в окружение PHP/Node,
а не отключайте проверку. По HTTP Digest не шифрует содержимое — используйте доверенную
камерную сеть/VPN. Редиректы не выполняются, пароли и содержимое ответов в журналы
адаптера не выводятся.

## Поведение событий и отказов

- Подписка: `/cgi-bin/eventManager.cgi?action=attach&codes=[VideoMotion]&heartbeat=10`.
- Передаются только `VideoMotion Start/Stop` канала 0. Multipart-разделители,
  heartbeat, посторонние события и другие каналы игнорируются.
- При подключении адаптер также запрашивает `getEventIndexes&code=VideoMotion`.
  Это восстанавливает уже активное движение после перезапуска. Запоздавший ответ
  не перекрывает более новое событие. Если запрос состояния не поддерживается,
  выдаётся предупреждение и приём новых событий продолжается.
- На обрыве активная обработка завершается состоянием `false`, чтобы FRS/LPRS не
  остался работать бесконечно. Это **сброс состояния из-за потери связи**, а не
  доказательство отсутствия движения. После восстановления выполняется повторная
  синхронизация. Переподключения — с задержкой до 60 секунд; после 401/403 — 60 секунд.
- Повторы одинакового состояния подавляются. В каждый момент отправляется не более
  одного запроса в RBT на камеру. При недоступности API хранится только последнее
  ожидающее состояние, поэтому память ограничена; промежуточные короткие движения
  могут быть объединены/потеряны. Это не надёжная очередь аудита и не exactly-once.
- Таймауты соединения и доставки ограничены. При SIGTERM подписки закрываются, и
  адаптер до 5 секунд пытается передать завершающее состояние `false`.
- У событий Dahua CGI нет надёжного времени в используемом формате; `date` — время
  доставки текущего состояния с сервера адаптера. Синхронизируйте часы серверов.

## Проверки

Без камеры, сети, БД, Redis и npm install, из корня репозитория:

```sh
php tests/dahua/driver.php
node --test tests/dahua/events.test.mjs
```

Дополнительный HTTP-тест поднимает только loopback-эмулятор, не обращается к реальным
камерам. Для среды, разрешающей локальные сокеты:

```sh
DAHUA_HTTP_INTEGRATION=1 node --test tests/dahua/events.test.mjs
```

До ввода в эксплуатацию на тестовой камере:

1. Зафиксировать модель/прошивку, сохранить исходную конфигурацию движения.
2. Проверить Digest, `magicBox.cgi?action=getSystemInfo`, снимок и чтение
   `configManager.cgi?action=getConfig&name=MotionDetect`.
3. Проверить четыре окна по 18 строк и ширину 22 ячейки; неизвестную схему не обходить
   выбором чужого драйвера. Проверить чувствительность и расписание в UI камеры.
4. С разрешения владельца записать тестовые зоны. Сравнить read-back и отображение в
   веб-интерфейсе камеры; проверить движение внутри и снаружи зоны.
5. Проверить `Start/Stop`, начальное состояние и heartbeat в CGI-подписке, а затем
   запуск/остановку FRS/LPRS. Сначала использовать тестовое распознавание **без реального
   открытия замков/шлагбаумов**.
6. Проверить потерю сети, восстановление подписки, остановку сервиса и отказ API RBT.
   Проверить, что другая камера продолжает обрабатываться независимо.
7. Восстановить согласованные рабочие зоны и настройки.
